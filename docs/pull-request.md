Loot Liquidator currently chooses among several overlapping reference/scenario paths, including tooltip occurrence/range proxies inferred from average yields. This change makes a versioned compiled itemdb the primary reference, resolves compatible source evidence per output, and uses the same final model for tooltips and processing value. Unknown fields remain unknown; missing quantities/prices cannot create a complete recommendation.

All installable addon files now live in `LootLiquidator/`. Runtime Lua files decrease from 24 to 17 through observation/native-bank event dispatchers and shared profession/settings ownership. The compact character roster and its Manual checkboxes are retained; profession profiles are nested below Professions & Alts. Database & Accuracy provides native checkboxes and 0–100 sliders with defaults itemdb 100, personal 60, TSM references 30, legacy disabled/10. Existing SavedVariables migrate additively.

The compiler ships 267 schema-validated source records: 248 provisional references and 19 documented smelting recipes. New independently reviewed database releases do not require engine changes. PR #4's adapter/tests are retained. There are no approved numeric coefficients in the reviewed registry, so no live skill multiplier is shipped. Recipe/build/context-scoped numeric transforms, explicit simulations and offline snapshots are supported conservatively; unsupported transforms retain an unadjusted reference. The newest 976-row research snapshot is retained separately as `LootLiquidator/itemdb.lua`; the active schema-1 database is `ItemDBRuntime.lua`. The ongoing research branch is not merged.

The alpha2 recorder replaces the old positive-only live collectors with one measured cast pipeline. It records recipe/build, measured context, nominal/net inputs, typed reagent returns and actual outputs; timeouts remain unresolved. Explicit operator-confirmed empty results contribute to zero-inclusive baselines. Study coverage gaps, simulations and mismatched characters cannot supply a personal estimate. Paged raw JSON can be structurally validated and staged using `tools/validate_craft_export.py`; no database or mechanic is approved automatically. Legacy aggregates/CSV remain inspectable. Personal tooltips use the same final model and show unscored confidence. All five previously reproduced scaling safety defects are fixed.

Validation: `bash tests/run.sh` passes deterministic artifact reproduction, Lua 5.1 syntax, package/load-order/XML checks, the preserved mechanics fixtures, 2,604 modernization assertions, native settings interaction fixtures, 87 measured-recorder assertions, 13 Python export-validation cases and all 13 profession-scaling audit checks. Six unchanged integration/data files are byte-identical to the PR #4 baseline. A synthetic 10,000-lookup comparison is slower in the weighted path (~7.4 vs ~4.6 µs/call); no overall or recorder performance improvement is claimed. Distribution/context caches are bounded; market prices are refreshed at valuation.

In-game testing is pending, particularly cast/result/bag event ordering, resource returns, rapid multi-craft sequences, and the native UI. Recrafts, customer orders, enchant-only results, unobserved reagent choices and reagent-bank inputs are unsupported as complete samples. Multi-input crafts remain exportable research rather than one-input valuations. See `docs/retail-qa.md` for bags/banks, BetterBags, ATT/tokens, TSM operations, profile scanning, native settings skins and observation QA. Older unversioned observations remain saved/exportable but are not silently promoted to current-build character evidence. Deprecated scenario slider values are preserved but no longer apply unsupported coefficients. Missing output rank/patch context may correctly produce Insufficient Data. Discrete quality/eligibility transformations await independently validated formula implementations.
