# Disenchant chance retention

The 0.12.42 baseline builder kept expected quantities while dropping independently measured occurrence and positive-stack bounds. Its shared inverse and forward curve also rebuilt material rows with quantities only, including at the unchanged zero profile. Consequently the tooltip showed a numerical value alongside “chance unavailable.” The source data still contained the chances.

The builder now retains usable source occurrence and bounds without copying cast counts into model observations. Identity transforms preserve those fields. Changed quantities do not generally identify a probability. A quality-only primary redistribution can use `P = E / fixed positive stack` when the source explicitly supports one fixed integer stack and its existing `E = P * stack` agrees. This is a modeled continuity assumption with the same confidence cap; it adds no target observations. This covers Crystal's conserved primary pool and Supplier before its quantity milestones. Supplier quantity milestones do not qualify for that inference. Variable-stack outputs and additional-material quantity priors retain unknown occurrence when no separate model identifies it.

Mixed-source updates retain an unchanged fused distribution, or apply the same fixed-stack check to the fused material. They retain per-material source estimates and weights. Source records, original counters, settings, and SavedVariables remain unchanged.

Zero-quantity endpoint identities remain available to the arithmetic but are omitted from the material display until their modeled allocation is positive. A valued simulated preview no longer labels character action access as an unavailable numerical model; action eligibility itself remains unchanged.

Regression coverage includes the shipped categories, reported epic items 272225 and 250462 at skill 0/64/104/290, exact zero-profile occurrence, capped fixed-stack inference, variable-stack rejection, the Supplier 19/20 and 29/30 transitions, and actual versus simulated access labels. The epic source prior is not a measured skill-zero cohort: its confidence remains capped rather than being promoted to high certainty.

The advanced controls also previously displayed the current character's saved manual profile beneath a scanned-character heading. They now read the selected character's captured skill plus equipment modifier once, and show uncaptured fields as unknown. Editing forks the displayed values into a simulation. Its stat calibration anchors are copied before the edit, and specialization stat changes are applied relative to the source allocation. A known operation uses its own captured allocation/buff receipt and recipe scope, rather than borrowing a later character snapshot. Unidentified source scopes use an explicit confidence-zero transfer model when those stats affect the result. Full observed source records and ordinary manual profiles retain their original contracts.
