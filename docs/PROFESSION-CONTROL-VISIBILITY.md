# Profession control visibility

The profession editor exposes only controls for supported item-tooltip processing. Enchanting controls disenchanting, Jewelcrafting prospecting, Inscription milling, and Mining smelting. Engineering retains recycling and learned crafting conversions; the other crafting pages retain their learned item conversions. Herbalism, Skinning and Fishing have no simulation pages. Native recipe identities remain available to actual item processing.

Open **Professions (Simulated) → a profession → Advanced**. Skill, invested points, relevant ratings/percentages and conditional bonuses are editable. A **Learned** checkbox represents a native learning grant at zero invested points; positive invested points imply learning without adding that grant twice. Structured prerequisites remain enforced. Editing selects the saved Simulated profile; Reset to minimum clears that profile without changing scanned character data or actual recipe access.

The controls affect quality, material quantities, additional drops or input savings. Multicraft applies only to eligible Craft outputs. Speed, concentration, ingenuity, gathering and unrelated crafting branches have no simulated controls or forecast calculations. Effects remain scoped to the correct profession, expansion, recipe labels, input rarity/class and target. Relevant conditional effects have explicit active-state controls; known aura IDs and stack caps use native data.



Static rules explicitly covering client12.1.5 can run on that version's compatible hotfix builds at or above their source build. Native captures remain exact to character, recipe, input allocation, build and freshness. An unknown later patch does not silently inherit an older numerical claim.

Confidence is the tooltip uncertainty signal. Assumptions and unresolved output identities stay in research/build metadata. Actual item outputs use the shared percentage, icon, name, quantity and value renderer. Presentation estimates never replace actual valuation quantities or net prices.
