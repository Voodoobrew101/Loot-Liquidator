# Owner Recycling pilot

The two pages are the owner's November6 export, preserved byte-for-byte with
hashes in `intake-review.json`. Their 46 accepted records are earlier disenchants;
they are not 46 new Recycling operations. Their duplicated diagnostic sections
contain20 unique successful Recycling casts with20 distinct typed result IDs.

`recycling-diagnostics.json` retains those diagnostics without rewriting their
method, coverage flags or rejected input deltas. `reported-result-events.json`
is a research-only extraction:44 R1 Evercores across the20 receipts, with each
cast's original context and rejection reason. It does not certify the old
five-item consumption history or promote an expected yield into shipped data.

`tests/test_recycling.lua` reads the diagnostic file directly to replay the
original typed results with synthetic input inventories and delayed bag updates.
The new complete records produced by that fixture are test outputs only.

After installing the repair, use Start new batch for new measurements. Keep the
old pilot for source review and comparison; resetting recorded results is not
necessary.
