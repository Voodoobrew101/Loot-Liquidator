## Independently inspected implementation behavior
1. [Disenchant.lua lines 97–105](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/Disenchant.lua#L97-L105) begins an operation on the player's `UNIT_SPELLCAST_SUCCEEDED` for spell 13262, then schedules a 3-second loot window. [Lines 109–118](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/Disenchant.lua#L109-L118) join recognized `LOOT_RECEIVED` `disenchant` outputs by the source's item key and add quantities. This is asynchronous capture, not a published complete external cohort.
2. **Critical denominator limitation:** [Disenchant.lua lines 64–68](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/Disenchant.lua#L64-L68) returns without persisting an operation when `#o.outputs == 0`. A missed/late/uncorrelated loot event or a hypothetical true zero-output success could be absent from the saved `crafts` table. Do not use saved row count alone as *all successful disenchants* for a per-output P(hit) or zero histogram without independent completeness evidence. This does **not** establish that zero-yield disenchanting really occurs or that any published sample is biased.
3. [Disenchant.lua lines 68–88](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/Disenchant.lua#L68-L88) can retain one `crafts=1` record per observed output-positive disenchant with input key, output keys/quantities, timestamp, source character and an `incomplete` flag if input/cost context is missing. [Lines 27–55, 119–135](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/Disenchant.lua#L27-L55) show input is inferred from pre-use, locked item or bag delta with timing constraints. This is not an at-cast item-level/bonus/skill/spec/patch/Resourcefulness proof; those must be verified from any actual export.
4. [Salvage.lua lines 16–45](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/Salvage.lua#L16-L45) intentionally groups the rendered summary by `ns.API.ItemKey.Base(r.input)`. Raw rows may retain a more specific key, but **displayed summary rows collapse bonus/stat variants**. Do not use the displayed Salvage summary as a rank-, itemLink-, or bonus-specific gear cohort.
5. **Historical retention:** [Workshop.lua line 24](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/Workshop.lua#L23-L25) defaults raw record retention to 90 days. [Retention.lua lines 20–44](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/Retention.lua#L20-L44) remove old `kind="salvage"` records from `root.crafts` **without aggregating them** (the recipe aggregates explicitly exclude salvage). A late SavedVariables copy or current UI total cannot be assumed to represent all-time operations.
6. [CraftTracker.lua](https://github.com/xLN1995/goblinomics/blob/a5c8cfdaed0bee823685f29e1a67d802f1c42fbc/Modules/Workshop/CraftTracker.lua) separately registers prospecting/milling/CraftSalvage results, but this QA has **not** established that those methods record all successful zero-output operations, exact rank or refund profiles; no universal cross-method denominator claim.
