## Terminal rejections and boundaries

Every remaining rejection names the examined values and the exact unsupported numerical interpretation, and states what new evidence would change that decision. Examples include unspecified inventory stacks with no verified unit size; prices with no quantity; quest counts that are not item-processing counts; mixed post-processing inventories with unresolved essence conversions; and an output-family anecdote that establishes neither amount nor denominator. These are completed current numerical decisions, not a request to reread every source or a rejection merely for missing a zero histogram.

An ambiguous same-name Looter row is preserved as a named family. Row order never establishes rank. Looter occurrence counters are retained even when quantity EV is rejected. A fixed positive-stack quantity is not an all-operation zero-inclusive histogram. Unknown source profile/gear variant/build stays unknown. A maxed or buffed study is never declared the minimum baseline; normalization requires a supported inverse, and no specialization or buff is applied twice.

No game actions, purchases, knowledge spending, new controlled batches, code commits, pushes, or external messages were performed. Firecrawl returned an out-of-credit error before retrieving a page; it was not retried. The available web tool retrieved Artisans, and the GitHub connector retrieved the primary native files. Access failures do not imply the source facts are false. The catalogue uses retained published extractions and scoped prior review facts where a fresh original retrieval was unnecessary.
