# Source memory, anti-repeat research, and QA learning (v1, 2026-10-28)

Mandatory for Master QA and all four workers. Research branch only; do not modify production addon code. This is **persistent learning through Git evidence and QA feedback**, not model weight training or self-modification.

## Source-review registry

The central searchable registry is generated by `node research/tools/build_source_memory.js` from:
- original observations in `research/evidence/observations/*.jsonl`;
- source assessment events in `research/coordination/source-reviews/*.jsonl` (worker-owned UNIQUE batch files; append by new file rather than update shared files);
- independent master decisions in `research/coordination/qa-feedback/*.jsonl` (master-owned UNIQUE batch files).

The generated `research/coordination/source-memory.json` is a **derived cache**, rebuildable by Master QA. Workers may read it but must also check recent events since its last build. Do not edit it individually. A URL is canonicalized (lower-case host, remove common trackers/fragments/trailing slash); stable study/dataset identifiers and reported parent/derivation relationships are additionally indexed. Exact URL duplicates are not automatically assumed to be independent experiments. A changed dataset revision may be a new cohort; stable URL alone must not suppress discoveries.

Each source entry reports source keys, URLs, observation IDs, study IDs, reviewed input/output record IDs, last assessed date, review disposition, last known change signal, known gaps, independent/cohort status, conflict notes, next-recheck trigger, reviewer and QA decision. Initial observations are marked **DISCOVERED/IMPORTED_UNREVIEWED**, not FULLY_ANALYZED just because a file exists.

## Required source workflow each worker run

1. Rebuild/read source memory or consult master-generated snapshot and new review events. Look up exact URL, studyID, dataset fingerprint, original cohort lineage, and record keys **before fetching the source externally**. Confirm the source URL is already available and recorded.
2. Decision: FULLY_ANALYZED + no change trigger -> **REUSE**, cite stored observation IDs; PARTIAL -> revisit only named gaps; NEEDS_RECHECK -> check only when patch/new comment/dataset revision or credible contradiction has occurred; DUPLICATE -> inspect primary dataset rather than re-count repost; NEW -> investigate and record. When prior work has insufficient evidence, keep it PARTIAL, not FULLY_ANALYZED.
3. When a previously examined source has additional relevant records, evidence of a changed page, new patch, conflicting study or explicit master reassignment, allow purposeful revisit and document reason. Never use 'already seen' to block meaningful new evidence.
4. Write a unique per-run `research/coordination/source-reviews/<worker>-<batch>.jsonl` containing JSON lines with `sourceUrl`, `studyID`, `datasetID`, `status`, `reviewedAt`, `recordKeys`, `observationIDs`, `missingFields`, `changeTrigger`, `revisitReason`, `originalStudyUrl`, `methodID`, `workerID`, `evidenceNotes`. Report avoided repeat fetches, purposeful revisits, new primary cohorts, linked duplicate reposts.
5. Never force publication of real character names or player-identifying private logs. URL tracking is for publicly reported studies.

## Research strategy learning / reward signals

Master QA reviews worker submissions against primary-source evidence and commits **independent** `qa-feedback` events. Workers cannot grant themselves rewards; link each event to unique `submissionID`, `claimID`, source lineage and stable record key. QA outcomes: ACCEPTED_NEW_EVIDENCE, ACCEPTED_REUSE, ACCEPTED_CORRECTION, USEFUL_NEGATIVE, NEEDS_WORK, REJECTED_UNSUPPORTED, REJECTED_DUPLICATE, REJECTED_CONTEXT_MISMATCH, RETRACTED. Original accepted claims subsequently retracted get a negative correction event; historical reports remain immutable.

Each master feedback event may include `strategyID` (e.g. ORIGINAL_DATASET, WOWHEAD_COMMENT, BLIZZARD_HOTFIX, REDDIT_PLAYER_STUDY, TSM_PRIMARY, PATCH_PAIR, REUSE_ARCHIVE, WIKI_GUIDE, FORUM_PRIMARY, OTHER), `workerID`, `sourceUrl`, `studyID`, `datasetID`, `claimID`, `recordKey`, `qaOutcome`, `reviewedAt`, `newValidatedFields` (0..4), `uniqueRecordsImproved`, `duplicateFetchAvoided`, `reproducibleCheck`, `estimatedMinutesSpent`, `costOfNewIngameSamplesAvoidedGold` (only documented), `reason`. Ensure one source event cannot multiply rewards across aliases or copied datasets.

**Feedback points for planning only (not evidence/confidence):**
- +6 ACCEPTED_NEW_EVIDENCE with a validated numeric field; +4 ACCEPTED_CORRECTION; +3 ACCEPTED_REUSE producing a new field-level finding; +2 USEFUL_NEGATIVE documenting a real blocker/contradiction; +1 a verified duplicate-fetch avoidance with cited cache; 0 NEEDS_WORK.
- -4 REJECTED_UNSUPPORTED or REJECTED_CONTEXT_MISMATCH; -3 REJECTED_DUPLICATE; -6 RETRACTED.
- Scoring is **per independently reviewed claim outcome**, not per links visited, output row copied, or number of papers agreeing. Cap each (original cohort, record key, field, discovery) to one positive reward in each version scope. No unverifiable savings or artificial bonuses for volume. Missing context may still earn USEFUL_NEGATIVE, not unsupported numeric confidence.
- Master summarizes recent approved events over the last 20–50 reviewed claims per strategy, noting sample size and rejection reasons; rank *source/strategy choices* by audited yield of useful evidence **per research effort**, with exploration of under-tested sources rather than indefinitely exploiting the apparent top source. Historical scores are priors, never proof a particular study is correct. Inspect old mistaken incentives if rewards rise while real field-confidence/coverage stagnate.

## Master QA responsibilities

Rebuild source-memory index, validate review-event schema, detect status conflicts, source ancestry and duplicate claims, issue feedback to workers with correction actions, update `research/coordination/research-lessons.md` using observed success/failure patterns, and report:
- new primary datasets vs copied sources; avoided repeat fetches vs justified revisits;
- independently accepted field-level contributions vs unsupported/retracted claims;
- per-strategy reviewed claim counts, QA acceptance fractions, reward points, and prioritized next source categories;
- evidence confidence and unique-record first-pass coverage as **separate** metrics.

**Never** reward a worker by raising numerical evidence confidence to meet a target. No change to the strict verification/patch/skill/stat gates or to original source data. Never call this automatic machine learning; agents improve future research choices by reading durable QA feedback.

## File schemas and build

Review event must have `sourceUrl`, `status`, `workerID`, `reviewedAt`; statuses: FULLY_ANALYZED, PARTIAL, NEEDS_RECHECK, DUPLICATE, DISCOVERED. Explicitly retain `missingFields` and `revisitReason` for incomplete or repeat work.
Feedback requires `qaOutcome`, `strategyID`, `workerID`, `reviewedAt`, `claimID` and `reviewer`. QA feedback is only authored by Master QA.
Run `node research/tests/test_source_memory.js` then `node research/tools/build_source_memory.js > research/coordination/source-memory.json`. Save generated snapshot only after verifying no concurrent source-event commits were missed. Output is research-only and never included in addon build.
