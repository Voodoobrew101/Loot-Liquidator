## Improved iterative instructions
- Start with GitHub PROGRESS, ledger, run log, actual main source and overlay. Preserve exact SHA and raw observations.
- Each batch target economically significant ore, herb, and disenchantable cohort; include crushing/shattering/smelting and historical gaps in subsequent batches. Verify velocity using current market evidence before calling an item highest-velocity.
- For each authentic input/output/condition profile record item IDs, patch/hotfix window, exact batch size, quality, skill, specialization, relevant stats, sample count, per-cast occurrence probability, observed integer conditional min/max, and unconditional decimal expected units separately. Never infer occurrence from total output counts alone.
- Label empirical, community, model, proxy, and prepatch data; do not merge different expansions, versions or player conditions. Grade per critical field using independent sources, representativeness, sample uncertainty and internal consistency; low N is a penalty, not an arbitrary universal score cap.
- Check p*min <= EV <= p*max only when all quantities are condition-matched; expected units alone determine gold valuation. No invented outputs or 90 scores.
- At end run independent QA and re-research lowest/highest-impact deficit; persist scores, blockers, next three targets, tests and read-back. No production modifications or invented in-game tests.
