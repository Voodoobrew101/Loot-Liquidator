## Source fields and integration boundaries

`dropChance` is a source occurrence reference K/N or H/N, never material units. `conditionalQuantity` is Q/H for recorded material-positive events, never a full completed-cast mean. Fixed positive stacks plus an identified source occurrence denominator can support a reference expected quantity; variable ranges without a distribution do not automatically supply a mean. A nominal-input reference retains its actual input denominator and leaves completed casts unknown. Current code must keep these fields separate, honor source filters and source profiles, and preserve named/unpriced materials.

Unknown same-name rank rows are not assigned IDs by table position and are not collapsed into a pooled occurrence probability. Native family mappings preserve species/rank alternatives; an unpriced family does not inherit one rank's market value. Knowledge-drop zeros require the source weekly/eligibility context and cannot become a zero baseline for eligible characters. The272246 CannotDE-versus-Looter conflict is preserved; a numeric source reference cannot grant recipe/item access.

The Enchantrix DE logger writes per material loot slot. Its Hsum is not an observed operation count or proof of one mutually exclusive primary output per cast. No synthetic one-primary event budget was applied without an independent era/rarity mechanism contract. Q==H records a positive-event mean1, not a hard population lower bound or a 100% chance.
